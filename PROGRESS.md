# PROGRESS — HW4 `ask_user`

## W2-0 — Tool contract (frozen before code)

`ask_user(question, options?, allow_free_text = true)`

### Inputs
- `question` — string, required. Empty or whitespace-only → validation **error**.
- `options` — optional array of `{ label, description? }`.
  - Empty-string / whitespace-only `label` → **error**.
  - Duplicate labels (after trim) → **error**.
  - An explicitly provided empty array (`options: []`) → **error**.
  - To ask an open question, **omit** `options` entirely (free-text-only when
    `allow_free_text` is true).
- `allow_free_text` — boolean, default **`true`**. When true, the picker appends
  the row **"Type your own answer…"**.

### Terminal behavior
- Renders the question, the numbered options, and (when `allow_free_text`)
  "Type your own answer…".
- **↑ / ↓** move the highlight in the options list.
- **Enter** selects the highlighted row. Selecting the free-text row opens an
  inline editor; **Enter** there submits the typed answer.
- **Esc** in the options list cancels the question.
- **Esc** while typing a free-text answer returns to the options list (it does
  **not** cancel).
- **Ctrl+C** cancels from anywhere (options list or editor).
- **Enter** on an empty typed answer returns to the options list; nothing is
  submitted.

### Return to the model
```json
{ "status": "answered" | "cancelled", "answer": string, "choice_index": number | null, "free_text": boolean }
```
- **Answered option** — `status: "answered"`, `answer: <label>`,
  `choice_index: <1-based index>`, `free_text: false`.
- **Free-text answer** — `status: "answered"`, `answer: <typed text>`,
  `choice_index: null`, `free_text: true`.
- **Cancelled** — `status: "cancelled"`,
  `answer: "no decision has been supplied"`, `choice_index: null`,
  `free_text: false`. The model **must not** pretend a choice was made.

## Decisions and why
- **Keep options optional + `allow_free_text` default true** — matches the
  required signature; a free-text-only prompt is a legitimate use.
- **Free-text row is appended, not counted in `choice_index`** — `choice_index`
  refers to real options only, so `null` unambiguously means "typed answer".
- **`exposure: "model-only"`** — `ask_user` is an orchestration/human tool; the
  Pi docs recommend `model-only` for tools that ask the user.
- **`status` field is authoritative** — the exact cancel string is also returned
  as `answer`, but consumers should branch on `status`.
- **Validation ("duplicate or empty options")** — *duplicate option labels* and
  *empty option labels* are errors, and an explicitly empty `options: []` is an
  error. Omitting `options` entirely is the supported way to ask a free-text-only
  question (requires `allow_free_text`, which defaults to true); with
  `allow_free_text: false` and no options, it is an error.
- **Editor keys are distinct from list keys** — in the free-text editor, Esc
  returns to the list and Ctrl+C cancels; on the list, Esc (or Ctrl+C) cancels.
  An empty typed answer returns to the list instead of submitting `""`.
- **Tests use the real TUI component** — `matchesKey`/`Key` are pure and the
  `Editor` accepts scripted input in Node, so only `ctx.ui.custom()` is mocked.
- **Tests must send raw terminal bytes** — `matchesKey("\r", Key.enter)` matches,
  but `matchesKey("enter", Key.enter)` does not. The W2-1 harness passed
  `Key.*` ids as data (6 timeouts); fixed in W2-2.
- **Test harness safety net** — the mocked `ctx.ui.custom()` resolves with a
  `{ __pending: true }` sentinel if no handler calls `done()`, so a missing
  branch fails an assertion fast instead of hanging for the 5 s timeout.
- **Published deps over `file:` paths** — reproducible installs and a real
  `npm audit`; both packages are pinned exactly at `1.1.0`.
- **Upgraded vitest 2.1.9 → 5.0.3** — the only remaining audit findings were in
  the dev toolchain (vite/esbuild/tinypool); vitest 5 is clean and the suite
  still passes. Extension runtime is unaffected either way.
- **Demos are operator-run** — `ask_user` requires a TTY; in `--print` / JSON /
  RPC it returns the "requires an interactive terminal UI" error, so the recorded
  demos must be interactive and are run by Joe (see `demo/RUN.md`).
- **Demo 1 data is pre-planted** — deterministic bursts make "the answer was
  used" checkable; the prompt asks the agent to use the provided file rather
  than regenerate it.
- **Model-free load smoke** — `discoverAndLoadExtensions` exercises Pi's actual
  jiti loader, proving the extension loads inside real Pi without needing a
  human or a model call.
- **`structuredContent` typing** — used an object `type` alias (not an
  `interface`) so TypeScript infers an index signature and it satisfies
  `JsonValue`.
- **Extension command, not prompt template** — `docs/prompt-templates.md` says
  templates are Markdown with no executable behavior; `docs/extensions.md`
  ("Choose an integration point") gives `pi.registerCommand()` for code that
  adds UI and runs work. `/ask_user` owns two pickers and a task, so it is a
  command.
- **`/ask_user` reuses the tool internals** — the picker was extracted into
  `runAskUser(params, ctx)`. `execute()` wraps its result into the tool contract;
  the command runs it twice and then does the task. The tool stays
  `exposure: "model-only"` (never callable via `ctx.executeTool()`), so the
  command must not depend on that path.
- **One transform, two call sites** — `applyPreset()` runs in both `execute()`
  and `renderCall()`, so the transcript line matches what actually runs.
- **Brute-force thresholds ride on env vars** — `BF_THRESHOLD`/`BF_WINDOW` keep
  the script runnable standalone (defaults 10/30) while letting the command pass
  the picked threshold.
- **Generated outputs are gitignored** — `incident_note.md`, `shift_handoff.md`,
  and `bruteforce_result.txt` are run artifacts, not source.
- **Free text off where a typed answer breaks the task** — `bruteforce` and
  `handoff` set `allow_free_text: false`; `incident` keeps it because its note
  records any text. The repeat question is also closed (`Pick another scenario`
  / `Exit`).
- **The repeat question exits on cancel** — unlike the scenario/task pickers,
  Esc/Ctrl+C at `Run another scenario?` ends with `Done.`, because quitting is
  the safe default there; reporting a cancellation would wrongly suggest an
  unfinished task.
- **The loop is command-only** — repeating scenarios is a UX decision for the
  command; the `ask_user` tool keeps its single-question contract.
